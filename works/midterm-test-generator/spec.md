# spec.md — 中間考査対策テスト自動生成スキル

## 目的

中学1年生の1学期中間考査に向けて、教科ごとに 10〜20問の小テストを **何度でも生成**できる仕組みを作る。最終的には HTML として GitHub Pages で閲覧可能にする。

## ユーザー確認済み事項

| 項目 | 決定内容 |
|------|---------|
| 対象教科 | 英語 / 数学 / 理科・社会 |
| 試験範囲の情報源 | 教科書のページ範囲と単元名を伝える（必要に応じて Claude が推定で補う） |
| 問題形式 | 穴埋め / 一問一答 / 選択式 / 正誤 をミックスして出題 |
| 配布形態の最優先 | HTML + GitHub Pages |

## デフォルト採用（変更希望があれば指摘してください）

| 項目 | 採用案 | 理由 |
|------|--------|------|
| 理科・社会の分割 | **個別スキル扱い**（`理科のテスト作って` / `社会のテスト作って` を別に処理） | 単元構成が違うため範囲ファイルも分ける方が現実的 |
| 解答表示 | **HTMLにトグル**（問題ごとに「答えを見る」ボタンで開閉）。印刷時用に「全て展開」ボタンも用意 | 印刷／画面学習どちらにも対応でき、答えを見ずに考える練習ができる |
| GitHub Pages 公開 | **まずはローカル生成のみ**。git init / GitHub リモート / Pages 有効化は別フェーズ | 段階的に進めた方が事故が少ない（範囲データが揃ってから公開判断できる） |
| スキル名 | `make-test` | Claude 側の trigger description で「〇〇のテストを作って」を拾わせる |
| スキルの設置場所 | `.claude/skills/make-test/SKILL.md`（プロジェクト内） | 試験範囲データもスキル本体もこのリポジトリに閉じる方が凝集度が高い。他リポジトリへの転用は必要になった時にコピーすればよい |

## ディレクトリ構成案

```
midterm_exam_preparation/
├── subjects/                       # 試験範囲データ（教科ごと）
│   ├── english.md                  # 教科書名・ページ範囲・単元名・重要語句リスト等
│   ├── math.md
│   ├── science.md
│   └── social-studies.md
├── docs/                           # GitHub Pages 公開用（index.html を置く想定）
│   ├── index.html                  # 教科一覧トップ（将来）
│   ├── english/
│   │   ├── 2026-05-12-001.html    # 生成された個別テスト
│   │   └── ...
│   └── ...（同様に math/science/social-studies）
└── works/midterm-test-generator/
    ├── plan.md / spec.md / todo.md / knowledge.md
    └── templates/
        └── test.html.tmpl          # 生成HTMLの雛形（CSS/JS含む）
```

設計のポイント：
- **試験範囲データはプロジェクト側**、**生成ロジック（スキル）はユーザー側**に置き、責務を分離
- 生成HTMLは `docs/` 配下に置く（GitHub Pages の標準ルート候補）。ファイル名は日付＋連番で履歴が残る
- HTMLテンプレートには Vanilla JS で「答え表示トグル」「全展開」「印刷ボタン」を実装（ライブラリ依存なし）

## スキルの動作仕様

トリガー例：
- 「英語のテスト作って」
- 「数学のテスト作って」
- 「理科のテスト作って」
- 「社会のテスト作って」

スキル実行時の処理：
1. 教科名から該当 `subjects/<教科>.md` を読み込む
2. 出題範囲・重要事項を踏まえ、**穴埋め/一問一答/選択/正誤** をミックスして 10〜20問生成
3. テンプレ `templates/test.html.tmpl` に流し込み、`docs/<教科>/<日付>-NNN.html` に出力
4. 生成パスとブラウザで開くコマンドをユーザーに提示

問題のバラつき確保：
- 出題範囲から **ランダム抽出**するため、毎回違うラインナップになる
- 同じ単元でも「穴埋め版」「正誤版」など形式を変えて再利用する

## 採用技術と選定理由

| 技術 | 採用 | 理由 / 代替案 |
|------|------|----------------|
| Vanilla HTML/CSS/JS | 採用 | 依存ゼロでブラウザ印刷可。代替: React/Vue は今回過剰 |
| Markdown (subjects) | 採用 | 中1の親が手で書きやすい。代替: YAML は構造化に有利だが書きづらい |
| Claude による問題生成 | 採用 | スキル呼び出しで都度生成。代替: 固定問題プールは「何度でも違うテスト」要件と合わない |
| GitHub Pages (将来) | 採用予定 | 無料・URL配布が容易。代替: Vercel は過剰、Notion 公開は印刷UIが弱い |

## 未確定・次フェーズで決めること

- 教科書の出版社・タイトル（出題精度に直結。例：英語 NEW HORIZON / NEW CROWN / Sunshine 等）
- 試験日・範囲の確定情報（ページ番号、単元名）
- スキルの最終的な「使うシーン」文面（trigger description）

## 進め方の提案（フェーズ分け）

1. **Phase 1（今回ここまで）**：仕様確定 + 雛形作成
   - `subjects/*.md` の空テンプレ作成
   - `templates/test.html.tmpl` の雛形作成
   - `make-test` スキルの SKILL.md 草案作成
2. **Phase 2**：範囲情報の流し込み
   - ユーザーが教科書情報・範囲を `subjects/*.md` に追記
   - 1教科で試験生成 → 表示確認 → 修正
3. **Phase 3**：GitHub Pages 公開
   - git init / GitHub リポジトリ作成 / Pages 有効化
   - `docs/index.html` の教科一覧トップ作成
