# knowledge — 社会の地図問題対応で学んだこと

## 設計判断

### `<use>` + `<g id>` 方式に切り替えた理由

最初は「ベースSVGを各問題内にインライン展開」する設計だったが、地図問題が3問あると同じSVG本体が3回コピーされHTMLが**膨大に**なる（4KB × 3 = 12KB の重複）。SVG の `<use>` は**同一ドキュメント内参照**なので「外部リソース禁止」ルールには触れない。`<defs>` 内に `<g id="world-map-defn">` を1つ置き、各問題で `<use href="#world-map-defn"/>` で参照する形に変更。最終ファイルサイズは 17KB（10問・地図3問入り）。

### `<symbol>` ではなく `<g>` を選んだ理由

`<symbol>` は独自の viewBox を持ち、参照側の `<svg viewBox>` との関係がやや複雑。一方 `<g>` は座標系を持たず、参照側の viewBox がそのまま適用されるので**直感的**。ベースSVGと利用側の viewBox が常に `0 0 1000 500` で揃うこのスキルでは `<g>` のほうが事故が少ない。

## ハマりポイント

### 1. xmllint の HTML パーサーは SVG タグを知らない

`xmllint --html --noout` で SVG タグに対し "Tag svg invalid" のエラーが出るが、これは libxml2 の HTML4 パーサーが SVG タグを未知のタグと判定するだけ。**HTML5 のインライン SVG は正式仕様**で、現代のブラウザは問題なくレンダリングする。検証目的では `xmllint --noout` を SVG ファイル単体にかけて well-formed XML であることを確認すれば十分。

### 2. SVG の text 要素を中央に置くのは `dominant-baseline: central`

番号マーカーの円の中央に数字を置くため、CSSで以下を指定：

```css
.map-num {
  text-anchor: middle;          /* 横方向の中央寄せ */
  dominant-baseline: central;    /* 縦方向の中央寄せ */
}
```

`text-anchor: middle` だけでは左右中央には来るが、上下は **テキストのベースライン基準**になるため、円の下半分にずれる。`dominant-baseline: central` を必ずペアで指定する。

### 3. 中精度SVGの座標は手書き近似値

`world-base.svg` の海岸線座標は Claude の地理知識から手書きで起こした近似値で、±数百km の誤差を含む。**正確な地理データではない**ことを忘れない：
- 「日本の正確な形」を問う問題には使えない
- 「○○の位置を地図上で示せ」程度なら問題なし
- 国境線は描いていない（海岸線のみ）

### 4. グリーンランドは大陸ではなく「世界最大の島」

地理問題で「六大陸」を出題するとき、グリーンランドを誤って大陸扱いしないよう注意。SVG では大陸グループ内に `<path id="greenland">` を置いてあるが、これは描画上の便宜であって、**地理的には島**。

### 5. `<use href="#id">` は SVG 2 で標準化された属性

古い SVG 1.1 では `xlink:href` を使う必要があったが、SVG 2 で `href` のみで動くようになった。Safari 12.1+ / Chrome 79+ / Firefox 51+ で対応。macOS の標準ブラウザなら全て OK。

## 仕様の罠

### 中精度の妥協点

ニュージーランド南島など、`world-base.svg` で「島が小さすぎて番号マーカーを置くと島がほぼ見えなくなる」ケースがある。半径14px の円は viewBox 1000x500 では大きめなので、**面積の小さい島を問う問題は避ける**か、マーカーを島の隣の海に置いて引き出し線で示す（未実装）。

### 等距円筒図法の特性

`world-base.svg` は等距円筒図法相当で、緯度経度が viewBox 座標と一次関数で対応する。よって：
- **緯度経度問題の答え合わせが機械的にできる**（座標から逆算可能）
- **高緯度の面積が極端に拡大される**（メルカトル図法ほどではないが）→「面積の大小」問題で南極が広大に見える点に注意

「面積の大小（ロシア・カナダ・アメリカ）」のような問題は、地図問題ではなく**テキスト一問一答で出す**ほうが学習効果が高い（高緯度の歪みで誤解させない）。
