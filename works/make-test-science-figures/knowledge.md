# knowledge — 理科の図問題対応で得たナレッジ

## 設計判断

### 「ベース図 1 枚 + 大量マーカー」ではなく「単元別図 SVG 群」を選んだ理由

社会の地図問題は世界地図 1 枚をベースに、`coords.md` から座標を引いて番号マーカーを上乗せする方式（ベース図使い回し）。理科でも同じ「単一ベース図」方式を検討したが却下した：

- 理科の植物分野は **単元ごとに見せたい図が違う**（花の断面 / 葉脈 / 根 / 胞子のう ...）
- 1 枚にまとめると情報過多で識別性が落ちる
- 各図を独立 SVG として管理した方が、将来 別単元（動物・実験器具）を追加するときの拡張性が高い

### 隠し `<defs>` + `<use href="#...">` 方式の踏襲

社会の地図問題対応で確立済みの「同一ドキュメント内 `<use>` 参照」方式を踏襲。理由：

- 1 つの図を複数問題で使い回すとき、SVG 本体は 1 コピーで済む
- 外部 SVG 参照禁止ルール（HTML 自己完結）に違反しない
- 6 種類の図を `<defs>` に登録 + 6 問で `<use>` 参照しても、HTML サイズは ~31KB に収まる

## ハマりポイント

### 1. `<defs>` 内の `<g id="...">` に `<defs><style>` を含めるとブラウザによっては効かない

`plant-classification.svg` には `<defs><style>...</style></defs>` でクラス定義を入れていたが、これを別 SVG の `<defs>` に再入れ子するときに挙動が読みづらい。今回の生成では `plant-classification.svg` を使わなかったので問題化しなかったが、次回使うときは **クラス参照を全てインライン属性に展開**する必要がある。

### 2. ラベル番号マーカー(r=14)が部位を覆い隠す

花の断面図で「柱頭」(200,110) の真上にマーカーを置くと、緑の盃形の柱頭そのものが赤い円で隠れる。今回の問題3では番号が部位の中心に乗っていれば「ここが何か」は分かるという判断で許容したが、より丁寧にやるなら：

- マーカーを部位の**横にずらす**（例：柱頭→(240, 90)）
- マーカー位置から部位への**引き出し線**(`<line>`) を追加

引き出し線方式は教科書スタイルに近く、視認性が高い。次回反復時に検討。

### 3. `<use>` 参照は同一ドキュメントなら CSS 属性も継承される

`<g id="flower-cross-section">` 内に `class="..."` を書いても、`<use>` 経由で参照したときに **外側 CSS の影響を受ける**。今回はインライン属性 (fill, stroke 直接指定) で書いたので問題なかった。クラス参照を使う場合は影響範囲に注意。

### 4. SVG 内の `<text>` を焼き込むと答えがバレる

最初のドラフトで `flower-cross-section.svg` に「柱頭」「子房」等のラベルテキストを焼き込んでしまうと、`<use>` 参照したテスト HTML で**答えが見えてしまう**。

→ 各 figure SVG は **ラベルテキストを書かない** ルールにした。
→ 例外：比較図 (`leaf-veins`, `roots`, `moss`) の `A` `B` ラベルは「どちらか」を問う問題で使うので残してよい。

## 改善案（次回反復時）

2. **plant-classification の活用**：ボックス文字を伏せたバリエーション SVG を別途用意し、「①〜⑤に入る分類名は？」型の問題を作る
3. **観察道具（ルーペ・顕微鏡）の図**：問1・問2 で図があった方が中学1年生には親切
4. **subjects/science.md の重要用語リスト充実**：問題文の精度が上がる
